# סימולציית הלוגיקה

סימולציה של **לוגיקת הבקרה בלבד**, ב-Python, בלי ספריות חיצוניות. היא לא מחליפה בדיקה ב-Zelio Soft 2 ולא בודקת חומרה.

## הקבצים

| קובץ | תפקיד |
|---|---|
| `../06_PLC_Logic/ladder_program.json` | **מקור האמת:** תוכנית ה-Ladder כנתונים |
| `ladder_engine.py` | מריץ את הלדר כמו שהוא, בשני מצבי סריקה |
| `reference_model.py` | מודל ייחוס שנכתב ישירות מהמפרט (`STATE_MACHINE.md`) |
| `plant.py` | מודל הציוד: לחצנים, חיווט קשיח, מגענים, חיישנים, תקלות מוזרקות |
| `signals.py` | גזירת שם המצב ושמות היציאות |
| `scenarios.py` | 20 תרחישי הבדיקה (S01–S20) |
| `run_simulation.py` | מריץ הכול וכותב את `08_Test_Reports/SIMULATION_RESULTS.md` |
| `test_logic.py` | בדיקות יחידה (מבנה התוכנית + תרחישים + השוואה) |
| `mutation_test.py` | בודק שהבדיקות תופסות כל היפוך מגע בלדר |

## הרצה

```bash
cd 07_Simulation
python3 -m unittest -v test_logic     # כ-20 שניות
python3 run_simulation.py             # כ-45 שניות, מעדכן את הדוח
python3 mutation_test.py              # כמה דקות
```

אחרי שינוי ב-`ladder_program.json` צריך להריץ את כל השלושה, וגם:

```bash
python3 ../tools/render_ladder_doc.py
```

## שלוש שכבות הבדיקה

1. **תרחישים:** כל תרחיש מגדיר אירועים (לחיצות, תקלות) ובדיקות בזמנים קבועים. הוא רץ על שלושה מנועים: הלדר בסריקה מיידית, הלדר בסריקה דחויה, ומודל הייחוס.
2. **השוואה אקראית:** קלטים אקראיים לאורך מאות שניות. הלדר ומודל הייחוס חייבים לתת **בדיוק** אותן יציאות בכל סריקה.
3. **מוטציות:** כל מגע בלדר הופך בתורו (NO↔NC), וחייבת להיכשל לפחות בדיקה אחת.

## הנחות שצריך לאמת ב-Zelio Soft 2

- סדר ההרצה: שורה אחרי שורה, מלמעלה למטה.
- תוצאת סליל זמינה לשורות שאחריו באותה סריקה. הלוגיקה נבדקה גם בהנחה ההפוכה, והתוצאות במצב היציב זהות.
- טיימר מסוג A מתאפס כשהפקודה שלו נופלת.
- כל הזיכרונות מתאפסים בכיבוי (בלי שמירת מצב).
