# SMART Voice · אתר נציג טלפוני AI

אתר נחיתה בעברית (RTL) לשירות נציג טלפוני מבוסס AI: עונה לשיחות, קובע תורים, ומעדכן יומן, וואטסאפ ו-CRM.
בנוי בהשראת המבנה של אתרי הקטגוריה המובילים, עם מותג, טקסטים ועיצוב מקוריים, ועם שדרוגים שלא קיימים שם.

## מה יש באתר

| סקשן | מה הוא עושה |
|---|---|
| Hero + **דמו חי** | מדברים עם הנציגה ישירות מהדפדפן (קול או כתיבה). היא עונה על שאלות ואף **רושמת ליד אמיתי** |
| הבעיות | שלוש השיחות שכל בעל עסק מכיר |
| שיחה לדוגמה | נגן שיחה עם תמלול, ומה קרה במערכות בזמן השיחה |
| המחקר | נתוני מהירות תגובה עם מקורות (HBR, Velocify, חוק הגנת הצרכן) |
| החבילה | Bento של כל מה שמקבלים |
| תחומים | 6 תחומים עם שיחה לדוגמה שאפשר להשמיע |
| **מחשבון חיסכון** | מחוונים, בחירת חבילה אוטומטית והכנסה שאפשר להציל |
| חיבורים | יומן, וואטסאפ, מייל, CRM, תורים, טלפוניה, API |
| וואטסאפ | אותו מוח גם בצ׳אט |
| ממשק ניהול | הדמיה אינטראקטיבית עם 6 לשוניות |
| תהליך, מחירון, שאלות נפוצות | כולל נתונים מובנים לגוגל (FAQ, Service, Organization) |
| יצירת קשר | טופס עם ולידציה, עובד גם בלי JavaScript, ולידים נשלחים ליעדים שתגדירו |

ועוד: מצב כהה, תפריט נגישות, הצהרת נגישות, מדיניות פרטיות ותנאי שימוש, כפתור CTA צף בנייד, תמונת שיתוף לרשתות, sitemap ו-robots.

## הרצה מקומית

```bash
cd voice-site
npm ci
cp .env.example .env.local   # אופציונלי, הכול עובד גם בלי
npm run dev                  # http://localhost:3000
```

בפיתוח, בלי יעד לידים מוגדר, לידים נרשמים ללוג של השרת.

## לפני שעולים לאוויר: מה למלא

כל מה שעסקי נמצא בקובץ אחד: [`src/config/site.ts`](src/config/site.ts).

1. **שם המותג ושם הנציגה** (`brand`). אחרי שינוי השם: `npm run og` מייצר מחדש את תמונת השיתוף.
2. **מחירים וחבילות** (`plans`, `pricing`). המחשבון, השאלות הנפוצות והסוכנת מתעדכנים מהם אוטומטית.
3. **הצהרות אמון** (`trust`): אזור השרתים, שפות וזמן הקמה. צריכים להיות נכונים לשירות שלכם.
4. **ערוצי קשר** ב-env: וואטסאפ, טלפון לסוכנת, מייל. מה שלא מוגדר לא מוצג.
5. **יעד לידים** ב-env (לפחות אחד): Webhook, מייל דרך Resend, או SMART CRM AI.
6. **עמודים משפטיים**: הטקסטים ב-`src/app/privacy`, `terms`, `accessibility` נכתבו כבסיס טוב, אבל כדאי שעו״ד יעבור עליהם. בהצהרת הנגישות חובה לציין איש קשר לנגישות (נלקח מ-`NEXT_PUBLIC_CONTACT_EMAIL`).

## לידים: לאן הם הולכים

כל ליד (מהטופס או מהסוכנת בדמו) נשלח **במקביל** לכל היעדים המוגדרים, ונחשב נשלח אם לפחות יעד אחד קיבל אותו.
בפרודקשן בלי אף יעד, הטופס מחזיר שגיאה ומציע ערוץ חלופי, כדי שליד לא ייעלם בשקט.

| יעד | משתנים | מה קורה |
|---|---|---|
| Webhook | `LEAD_WEBHOOK_URL`, `LEAD_WEBHOOK_SECRET` | POST עם JSON. חתימה: `X-Signature: t=<unix>,v1=<hmac-sha256 של "t.body">` |
| מייל | `RESEND_API_KEY`, `LEAD_EMAIL_TO`, `LEAD_EMAIL_FROM` | מייל בעברית עם קישור חיוג |
| SMART CRM AI | `SMART_CRM_API_URL`, `SMART_CRM_API_KEY` | איש קשר בשלב ״ליד״ + משימת חזרה בעדיפות גבוהה |

אבטחה בנתיב הלידים: ולידציה עם zod, הגבלת גודל בקשה (גם בהעלאה בזרם), honeypot נגד בוטים, חסימת POST מאתר זר,
ומכסת לידים משותפת לטופס ולדמו לפי IP (`LEAD_RATE_LIMIT_PER_HOUR`, ברירת מחדל 6). ליד מהדמו נשמר רק אם המספר נאמר בפועל בשיחה,
כך שאי אפשר לזייף ליד במכה אחת. ההגבלה נשמרת בזיכרון של כל מופע שרת: ב-Vercel ה-IP מגיע מהפלטפורמה, ובשרת עצמאי צריך proxy שמוסיף X-Forwarded-For.

## הסוכנת בדמו החי

- **זיהוי דיבור והקראה** נעשים בדפדפן (Web Speech API): עובד ב-Chrome, Edge ו-Safari. בדפדפן בלי תמיכה עוברים אוטומטית לכתיבה.
- **בלי מפתח API**: מנוע שיחה מובנה בעברית (`src/lib/agent/rules.ts`) שעונה על מחיר, הקמה, חיבורים, וואטסאפ, פרטיות ועוד, ואוסף שם, עסק וטלפון (כולל מספר שנאמר במילים) לפני שמירת ליד. אפס עלות לשיחה.
- **עם `ANTHROPIC_API_KEY`**: Claude מנהל את השיחה עם כלי `save_lead`, על בסיס אותו ידע מקובץ ההגדרות. כל תקלה נופלת חזרה למנוע המובנה, כך שהדמו לא נשבר.

## בדיקות

```bash
npm run lint && npm run typecheck   # סטטי
npm test                            # בדיקות יחידה (Vitest)
npm run build && npm run test:e2e   # בדיקות דפדפן (Playwright) כולל סריקת נגישות axe
```

בדיקות ה-E2E מריצות את האתר האמיתי מול Webhook מדומה ובודקות: טופס (כולל בלי JavaScript), שיחה מלאה עם הסוכנת עד שמירת ליד חתום,
נגישות WCAG 2.1 AA במצב בהיר וכהה, מחשבון, לשוניות במקלדת, מצב כהה, נייד בלי גלישה לרוחב, וחסימת ספאם ו-POST מאתר זר.

## פריסה ל-Vercel

1. New Project → בוחרים את הריפו → **Root Directory: `voice-site`**.
2. מוסיפים את משתני הסביבה מ-`.env.example` (לפחות `NEXT_PUBLIC_SITE_URL` ויעד לידים אחד).
3. Deploy. האזור מוגדר ל-`fra1` ב-`vercel.json`.
