# דוח נגישות — Ori Travel AI (V6)

> נבדק על ידי הסוכן VIS-A11Y. שיטה: ביקורת מבוססת-ראיות על ה-DOM וה-computed styles (ללא axe — לא מותקן), מקודדת כבדיקות Playwright
> ב-`apps/web/e2e/visual/a11y.*.spec.ts`. כל הבדיקות רצות מול build טרי של האפליקציה (FastAPI מגיש את `dist`), נתוני DEMO בלבד.
> היקף: 11 מסכים (התחברות, דשבורד, טופס טיסות, תוצאות טיסות [רשימה + טבלה + לוח מחירים + מבצע + מפה], תוצאות מלונות, פרטי טיול, סקירת הזמנה,
> דף ספק DEMO, משפחה, הגדרות) × 1440px / 390px × ערכה בהירה / כהה.

## 1. סיכום

| תחום | תוצאה |
|---|---|
| h1 יחיד, `<main>`, `<nav>`/`<header>`, `dir=rtl`, `lang=he`, כותרת מסמך | עובר בכל המסכים, **חוץ מדף ספק ה-DEMO (אין h1 — A11Y-01)** |
| שם נגיש לכל אלמנט אינטראקטיבי; תווית לכל שדה; alt לתמונות; אין id כפולים; אין דילוג רמות כותרת | עובר (0 ממצאים) ב-44 שילובי מסך×רוחב×ערכה |
| ניגודיות טקסט (WCAG AA) — כל צמתי הטקסט הנראים | **1 חריגה** בלבד (A11Y-03, ערכה כהה), מתוך ~8,900 צמתי טקסט שנדגמו |
| מטרות מגע ≥ 44×44 ב-390px | 16 קבוצות אלמנטים קטנות (A11Y-05); כפתורי `.touch-target` עוברים (אזור לחיצה 44px דרך `::after`) |
| פוקוס גלוי | עובר: כל עצירות ה-Tab (60 עצירות בדף התוצאות) בעלות outline/ring, בהירה וכהה |
| סדר Tab בדף הטיסות | עובר: קישור דילוג → ניווט → סיכום החיפוש → לוח המחירים → תוצאות |
| לוח מחירים במקלדת | עובר: חצים (מודעי RTL), Home/End, roving tabindex (עצירה אחת), Enter בוחר תאריך ומריץ חיפוש; מטריצה: חצים דו-ממדיים |
| דיאלוגים | עובר: פוקוס נכנס, כלוא (25×Tab + 25×Shift+Tab), Escape סוגר, פוקוס חוזר לכפתור הפותח (דיאלוג פריט ידני + דיאלוג אישור ביטול הזמנה) |
| `prefers-reduced-motion` | עובר: 0 אלמנטים עם transition/animation > 100ms, 0 אנימציות אינסופיות; בדיקת שפיות — בלי ההעדפה יש תנועה |
| RTL | עובר: סרגל צד בימין, h1 מיושר להתחלה, 0 אלמנטים עם `text-align` פיזי; 0 גלישה אופקית ב-390px (חוץ מ-A11Y-02) |
| זום 200% (חלון 720px) ורוחב 320px | 0 גלישה אופקית בכל הזרימות הראשיות (חוץ מ-A11Y-02 ב-320px); כפתורי "חיפוש" ו"כניסה" נגישים בגלילה |

## 2. ממצאים

| מזהה | חומרה | מסך | אלמנט / selector | ראיה | מקודד בבדיקה |
|---|---|---|---|---|---|
| **A11Y-01** | בינונית | `/demo-supplier/checkout` | הכותרת "דף ספק לדוגמה — DEMO, אין חיוב" היא `<div>` | `h1` count = 0 בכל 4 השילובים (בדף יש `<main>`, אין `<nav>`/`<header>`) | `a11y.structure.spec.ts` › "A11Y-01" — `test.fail` |
| **A11Y-02** | בינונית | `/demo-supplier/checkout` ב-390px / 320px | כותרת הדף (שורה אחת ללא עטיפה) | `scrollWidth − clientWidth = 42px` ב-390px; גם ב-320px | `a11y.structure.spec.ts` › "A11Y-02" + reflow@320 — `test.fail` |
| **A11Y-03** | נמוכה-בינונית | תוצאות טיסות, ערכה כהה, 1440px | `button[data-testid=fare-cell] > span.text-xs.font-semibold` — מספר היום בתא "הזול ביותר" (tangerine) | `#c4ccd8` על `#8a4613` = **4.37:1** (נדרש 4.5:1). הטקסט משתמש ב-`text-ink-700` שמתהפך לבהיר בכהה, והרקע heat-best נשאר כתום כהה; הטבלה ב-design-system §4 מכסה רק `fg`/`heat-best` (6.25) | `a11y.contrast.spec.ts` › "A11Y-03" — `test.fail`; הלולאה הכללית מחריגה אותו במפורש |
| **A11Y-05** | נמוכה-בינונית | ראו §4 | קישורי טקסט, `select`/`input` קטנים, `range`, צ'קבוקס 20px, `<summary>` | מידות מחושבות ב-390px עם מצביע גס (ראו טבלה) | `a11y.contrast.spec.ts` › "A11Y-05" — `test.fail`; יתר המסכים נבדקים מול רשימת חריגים מוכרת (כל הפרה חדשה תיכשל) |

אין ממצאי "חמורה/קריטית": אין אלמנט ללא שם, אין שדה ללא תווית, אין מלכודת מקלדת, אין איבוד פוקוס בדיאלוגים.

מה **לא** כולל הסריקה (מגבלות): טקסט על תמונות/גרדיאנטים מחושב מול צבע הרקע המוצק הקרוב (הדגימות עם `bgImage` מסומנות בנתונים הגולמיים);
קוראי מסך אמיתיים לא הורצו; אנימציית "scroll-snap" במסכי מגע לא נבדקה במכשיר פיזי.

## 4. מטרות מגע ב-390px (A11Y-05)

המדידה: `getBoundingClientRect` של האלמנט, מוגדל ב-`::after` של `.touch-target` כשהמצביע גס (Playwright `hasTouch`, `(pointer: coarse)` מאומת).
צ'קבוקסים/רדיו בתוך `<label>` נמדדים לפי ה-label. קישורים בתוך משפט (חריגת WCAG 2.5.8) לא נספרים.

| אלמנט (טקסט) | גודל (px) | מסכים |
|---|---|---|
| קישור "ניהול ספקים ואבחון" (פס הספקים) | 98×16 | תוצאות טיסות/מלונות |
| קישור "ספקים ואבחון" | 81×20 | דשבורד |
| כפתור "כיוון אחד" / "הלוך-חזור" (`Segmented` בטופס) | 85×36 | טופס טיסות |
| כפתור "אפשרויות נוספות" | 130×36 | טופס טיסות |
| `<summary>` "איך לקרוא את הלוח ומאיפה המחירים" | 197×19.5 | תוצאות טיסות |
| קישורי "ייצוא ליומן (ICS)" / "ייצוא ל-PDF" | 155×40 / 129×40 | פרטי טיול |

## 5. איך להריץ

```
cd apps/web
npx playwright test e2e/visual/a11y --project=desktop      # שלוש קבצי ה-a11y
```
דרישות: שרת FastAPI עם build טרי ונתוני demo (ראו `docs/release/visual-qa.md` §5). משתני סביבה: `VIS_BASE_URL`, `VIS_OWNER_EMAIL`, `VIS_OWNER_PASSWORD`, `VIS_WORK_DIR`.
הבדיקות בוחרות רוחב/ערכה בעצמן ולכן רצות רק בפרויקט `desktop`. כשתוקן באג — להסיר את ה-`test.fail` (הבדיקה תדווח "expected to fail but passed").

קבצים: `a11y.structure.spec.ts` (מבנה, RTL, גלישה, זום 200%/320px), `a11y.contrast.spec.ts` (ניגודיות, מטרות מגע), `a11y.keyboard.spec.ts` (פוקוס, סדר Tab, לוח מחירים, דיאלוגים, תנועה), `a11y-lib.ts` (פונקציות הביקורת בדפדפן), `a11y-screens.ts` (רשימת המסכים).
