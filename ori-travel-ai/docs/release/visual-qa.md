> נכתב על ידי הסוכן VIS-A11Y. תמונות: `docs/release/screenshots/`. בסיסי הרגרסיה החזותית: `apps/web/e2e/visual/visual.spec.ts-snapshots/` (58 קבצי PNG).

## 1. רגרסיה חזותית (Playwright `toHaveScreenshot`)

**כיסוי:** 15 מסכים/רכיבים × {1440px, 390px} × {בהיר, כהה} = **58 בסיסים** (טבלת התוצאות היא בלבד לדסקטופ: ב-390px התצוגה היא כרטיסים).
מסכים: התחברות, דשבורד, טופס טיסות, לוח מחירים (חודשי + מטריצת לילות), כרטיס "המחיר הנמוך בחיפוש", מפת מסלול, כרטיס תוצאה (רשימה), טבלת תוצאות (דסקטופ), תוצאות מלונות, פרטי טיול (ציר זמן + תקציב + תג חפיפה), סקירת הזמנה (מוכן לאישור), דף ספק DEMO, משפחה, הגדרות.

**יציבות (נבדק):** הבסיסים נוצרו, ואז הורצו פעמיים ברצף — **58/58 עברו בשתי ההרצות, 0 הבדלי פיקסלים** (ההרצות כללו חידוש אוטומטי של נתוני הבדיקה — מזהים וחותמות זמן שונים — ולכן המסכות עובדות בפועל).
בדרך תוקנו מקורות חוסר-יציבות: שעון קפוא (`page.clock.setFixedTime`), תאריכי חיפוש קבועים (12–17 בינואר 2027), `reducedMotion: 'reduce'` + CSS שמבטל אנימציות/קרט, המתנה ל-`document.fonts.ready` ול-`networkidle`,
מסכות (magenta) על טקסט דינמי (זמני "נבדק/עודכן", "לפני/בעוד X", חותמות זמן, מזהים ארוכים, אסמכתאות `DEMO-…`) ועל כרטיסי "חיפושים אחרונים/טיולים קרובים" בדשבורד (נצברים עם הזמן), סרגלים דביקים/קבועים מנוטרלים בצילום רכיב,
ותגובת לוח המחירים נשמרת בדיסק ומוגשת מחדש (נקודת הקצה מוגבלת ל-10 בקשות ל-10 דקות למשתמש, והנתונים קבועים).
סטייה מותרת: `maxDiffPixelRatio: 0.002`.

**הרצה:**
```
npx playwright test e2e/visual/visual.spec.ts --project=desktop            # השוואה
```
**עדכון בסיסים** (אחרי שינוי עיצובי מכוון — לבדוק ב-diff לפני):
```
npx playwright test e2e/visual/visual.spec.ts --project=desktop --update-snapshots
git add apps/web/e2e/visual/visual.spec.ts-snapshots
```
הבסיסים תלויים בפלטפורמה (Chromium על Linux; הסיומת `-desktop-linux.png`). ב-Windows/CI אחר יש ליצור בסיסים נפרדים או להריץ ב-Linux/Docker.
בדיקות ה-visual וה-a11y מנהלות בעצמן viewport וערכת צבע ולכן מדלגות על פרויקט `mobile`.

## 3. הבדלים מכוונים מהסרטון

- **עיצוב מקורי, ללא מיתוג מועתק:** שם/לוגו "Ori Travel AI", פלטת טורקיז + "טנג'רין" למבצעים + "שמיים" למחירים נמוכים — לא שחזור של אתר קיים.
- **הכול מסומן DEMO:** תג "הדגמה" על כל מחיר/הצעה, פס "מצב הדגמה", הערת כיסוי ("חלק מהתוצאות הן נתוני הדגמה", "אין התחייבות לכיסוי מלא"). המחירים סינתטיים ולא משקפים שוק.
- **לוח המחירים לא מבצע בקשות לספקים חיים** (עלות ומגבלות קצב) — מסומן במקרא ובהערת הכיסוי; תאים ללא נתון מסומנים "לא נבדק", ימים ללא שירות "אין טיסות".
- **ניסוח זהיר:** "הזול ביותר מבין ההצעות שנמצאו" — לא "הטיסה הכי זולה".
- **אין רכישה אוטומטית:** "הכנת הזמנה" → בדיקת מחיר מול הספק → אישור מפורש עם סיסמה → סימולציה או "השלמה באתר הספק" (דף ספק DEMO, ללא חיוב).
- **מפה ללא אריחים/בקשות חיצוניות;** בסיס Natural Earth מפושט.
- **מובייל = כרטיסים** במקום טבלה.

## 4. ממצאים חזותיים/UX לתיאום (לא באגים חוסמים)

1. **A11Y-01/02 — דף ספק DEMO:** אין `<h1>`, וגלישה אופקית של 42px ב-390px (ראו `docs/release/accessibility-report.md`). חזותית גם: אין תפריט/ניווט (מכוון — דף "אתר חיצוני"), אך כותרת הדף נחתכת במובייל.
2. **A11Y-03 — ערכה כהה:** מספר היום בתא "הזול ביותר" בלוח המחירים 4.37:1.
3. **A11Y-05 — מטרות מגע** קטנות מ-44px בקישורי עזר, `<summary>`, סליידרי הגדרות ו"כיוון אחד/הלוך-חזור" (טופס טיסות).
4. **שעון הדפדפן מול השרת:** בבדיקה עם שעון קפוא "נבדק" הוצג כ"בעוד 8 שע'" — תוצר של הקפאת השעון בבדיקות בלבד (נמסך בבסיסים), לא באג מוצר.
5. סקירת הזמנה: אחרי כמה דקות ללא בדיקת מחיר מוצגת הודעה "בדיקת המחיר האחרונה אינה עדכנית" והשלב "אישור התנאים" נעלם עד בדיקה מחדש — תקין, ולכן בדיקות החזותי/נגישות מריצות `revalidate` לפני פתיחת הדף.

## 5. סביבת הרצה (לשחזור)

```
cd apps/web && npx vite build --outDir /tmp/claude-0/vis/dist
cd ../api && export ORI_DATABASE_URL=sqlite:////tmp/claude-0/vis/vis.db ORI_DATA_KEY=$(.venv/bin/python -m app.cli gen-key) ORI_SERVE_WEB=true ORI_WEB_DIST_DIR=/tmp/claude-0/vis/dist
.venv/bin/python -m app.cli migrate
ORI_OWNER_PASSWORD='Vis-Owner-Pass-123' .venv/bin/python -m app.cli create-owner --email owner@vis.local --name "בעלים" --password-env ORI_OWNER_PASSWORD
.venv/bin/python -m app.cli seed-demo
.venv/bin/uvicorn app.main:app --no-proxy-headers --host 127.0.0.1 --port 8082
# ואז, מ-apps/web (ברירות המחדל תואמות: http://127.0.0.1:8082, owner@vis.local):
npx playwright test e2e/visual --project=desktop
```
נתוני הבדיקה (חיפוש טיסות/מלונות עם תאריכים קבועים, טיול עם מלון חופף, הזמנה "מוכנה לאישור", הזמנה עם מעבר לדף ספק DEMO) נוצרים אוטומטית ב-`e2e/visual/helpers.ts` ונשמרים 20 דקות ב-`$VIS_WORK_DIR` (ברירת מחדל `/tmp/ori-vis`).
תמונות לדוח: `VIS_REPORT=1 npx playwright test e2e/visual/report-screenshots.spec.ts --project=desktop` (שעון אמיתי, ללא מסכות).

## 6. נוהל baseline קנוני (נוסף באימות הסופי)

לוח הבקרה מציג חיפושים אחרונים וטיולים, ולכן גובה הדף תלוי בנתונים שקיימים ב-DB. התוכן עצמו מוסתר
במגנטה, אבל הגובה משתנה. לכן ה-baselines נוצרים ונבדקים **תמיד על DB נקי**, ובסדר קבוע:
1. `migrate`, יצירת בעלים ו-`seed-demo` (סעיף 5).
2. `visual.spec.ts` רץ **ראשון**, לפני בדיקות a11y, כי אלה יוצרות נתונים נוספים.

אחרי שה-baselines של dashboard נוצרו מחדש בנוהל הזה (2026-11-12), ריצה על DB נקי נוסף עברה 58/58.
