## 1. נכסים

| נכס | רגישות |
|---|---|
| פרטי מסמכים של נוסעים: דרכון, תאריך לידה, שם משפטי | גבוהה מאוד |
| חשבונות משפחה: סיסמאות ותפקידים | גבוהה |
| מפתחות API של ספקים ושל ספק ה-AI | גבוהה (גניבה = עלות כספית) |
| אישורי הזמנה ומכונת המצבים | גבוהה (כפילות = חיוב כפול בעתיד) |
| היסטוריית חיפושים, טיולים ומועדפים | בינונית (מידע על תוכניות נסיעה ועל היעדרות מהבית) |
| יומן ביקורת | בינונית |

## 2. גבולות אמון
1. הדפדפן ↔ ה-API (HTTP מקומי, וב-production HTTPS בלבד).
2. ה-API ↔ ספקים חיצוניים. כל תוכן שמגיע מהם **לא אמין**: טקסט, קישורים, מספרים לא תקינים.
3. ה-API ↔ מודל AI. הקלט מהמשתמש ומהספקים לא אמין, והפלט של המודל לא אמין.
4. התהליך ↔ הדיסק: קובץ ה-SQLite וקובץ `.env`.

## 4. מגבלות ידועות (בכנות)

* **מפתח ההצפנה המקומי** יושב ב-`apps/api/.env` על אותו דיסק כמו ה-DB. ההצפנה מגינה מפני דליפה
  של קובץ ה-DB או של גיבוי שלו, ולא מפני תוקף עם גישה מלאה למחשב. בסביבה רצינית צריך לשמור את
  המפתח ב-Windows Credential Manager או במנהל סודות.
* **Rate limiting בזיכרון** מתאים לתהליך יחיד. ריבוי תהליכים ידרוש Redis או מנגנון דומה.
* **HTTP מקומי:** ב-localhost העוגיות לא מסומנות `Secure`. כשחושפים את השרת ברשת חובה HTTPS
  ו-`ORI_COOKIE_SECURE=true`.
* **אין MFA** ב-V1. ההגנה היא סיסמה חזקה, נעילה ו-reauth לפעולות רגישות.

## 5. מה אסור (מדיניות)
* לעקוף captcha, תנאי שימוש או מגבלות קצב של ספקים, או לבצע scraping.

* לתת ל-AI לבצע או לאשר הזמנה.
* לפרוס ל-production בלי אישור מפורש של בעל החשבון.
