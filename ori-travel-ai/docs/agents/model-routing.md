# ניתוב מודלים — מה אומת ומה לא

## מה נבדק בפועל
* **הסשן הראשי (המנהל):** `get_session` החזיר `configured_model: claude-opus-5-5` וגם
  `last_served_model: claude-opus-5-5`. זה המודל היחיד שזהותו **אומתה**.
* **סוכני-משנה:** הכלי `Agent` מקבל פרמטר `model` עם הערכים `opus`, `sonnet`, `haiku` ו-`fable`.
  ההנחיות של הסביבה מתארות אותם כ-Opus 5.5 (`claude-opus-5-5`), Sonnet 5.5 (`claude-sonnet-5-5`),
  Haiku 5.5 (`claude-haiku-5-5`) ו-Fable 5.2 (`claude-fable-5-2`).
  **אין דרך לאמת מבפנים איזה מודל באמת הגיש כל סוכן-משנה.** לכן הטבלה מתעדת את **המודל שנדרש**,
  והסביבה קיבלה את הבקשה בלי שגיאה.
* **עלויות ומכסות:** לא נמצאה בסשן נקודת קצה שמציגה מחיר לכל סוכן. `get_session` החזיר
  `rate_limit_info.status: allowed` (מכסה שבועית). לא בוצעו קריאות API בתשלום מחוץ לסשן.

## מיפוי שביקש בעל החשבון מול מה שהופעל בפועל

| העדפה (תווית של בעל החשבון) | alias בכלי | שימוש בפועל |
|---|---|---|
| Opus 5.5: מנהל, ארכיטקט, ראשי צוותים, אינטגרציה קשה | `opus` (וגם הסשן הראשי) | הסשן הראשי, B2, B5, F1, BE-CAL, FE-FLIGHT, UX-DS |
| Fable 5.2: ביקורות אבטחה והזמנות קריטיות | `fable` | B4 (בטיחות הזמנות), AUD (ביקורת בלתי-תלויה), BOOK-REDIRECT, RELEASE-AUDIT (מתוכנן) |
| Sonnet 5.5: קוד ממוקד, בדיקות, תיעוד | `sonnet` | R1, B1, B3, B6, F2, F3, F4, D1, QA, BE-TRIPS, PROV-ANALYST, E2E ו-DevOps (מתוכנן) |
| Haiku | `haiku` | לא בשימוש. אין משימה שבה החיסכון מצדיק את הסיכון לאיכות |

## מדיניות חיסכון
* לא יותר מ-6 סוכנים במקביל. המכונה עם 4 ליבות, ועוד הרצות בדיקות.
* סוכן שסיים ונדרש לתיקון **מחודש עם ההקשר שלו** (SendMessage), ולא מוחלף בסוכן חדש.
  כך נעשה ל-B1, B4, B5 ו-F3 אחרי הביקורת.
* fable רק למשימות שבהן טעות עולה ביוקר: הזמנות, ביקורת.
