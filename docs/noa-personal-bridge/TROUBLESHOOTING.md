# פתרון תקלות — NOA Personal Bridge

כל שורה בנויה כך: **סימפטום**, אחריו **סיבה אפשרית**, ואחריה **מה עושים**. כל ההודעות בעברית מופיעות כאן בדיוק כפי שהן מוצגות באפליקציה או מוחזרות מהשרת. הטקסטים שבמירכאות לקוחים מהקוד.

> אם קורה משהו מסוכן (טיוטה מקבוצה, שליחה לשיחה הלא נכונה, שליחה כפולה, שליחה מהמספר השני): **עצירת חירום** מיד, לא לנסות שוב, ולתעד.

## בדיקה מהירה לפני הכול

```powershell
curl.exe http://127.0.0.1:8787/health
curl.exe https://<הכתובת-שלך>/health
```

התשובה צריכה להיות `{"ok":true,"enabled":true,"engine":"...","version":"0.1.0"}` בשתי הכתובות. אם רק הבדיקה המקומית עובדת, הבעיה במנהרה. אם גם היא לא עובדת, הבעיה בשרת.

| סימפטום | סיבה אפשרית | מה עושים |
|---|---|---|
| הודעות ממספרים שלא שמורים אצלך, הודעות עם רצפי ספרות (קודים, סכומים), והודעות שמגיעות אחריהן עד שקוראים אותן, לא מקבלות טיוטה (ההיקף המדויק לפי דיווחים, ולא נבדק על המכשיר) | **הסתרת תוכן רגיש ב-Android 15 ומעלה.** המערכת מחליפה את הכותרת ב-"WhatsApp" ואת הטקסט בהודעה קבועה. האפליקציה מזהה את זה ומדלגת בכוונה, כדי לא לנסח (ולא לשלוח) תשובה על הודעה שהיא לא ראתה | זו התנהגות צפויה, ואין בה תקלה. לשמור אנשי קשר חשובים באנשי הקשר עוזר לחלק מהמקרים. **עקיפה אופציונלית** בסוף הטבלה |
| אין טיוטות מקבוצות | מכוון: רק שיחות פרטיות | אין מה לתקן |
| שיחה פרטית מסוימת אף פעם לא מקבלת טיוטה | (א) היא ברשימת ההחרגות. (ב) האפליקציה לא הצליחה לקבוע בוודאות שזו שיחה פרטית (למשל חשבון עסקי, Meta AI, או התראה במבנה לא רגיל). במקרה כזה היא מדלגת בכוונה | (א) **הגדרות** ‏› **שיחות שלא יקבלו טיוטות** ‏› **הסרה**. (ב) זו התנהגות מכוונת (fail-closed). אפשר לתעד במסגרת בדיקה R4 / R11 |
| ההתראה מציגה רק "N הודעות חדשות" | התצוגה המקדימה של ההודעות כבויה ב-WhatsApp, Chat lock, או נעילת אפליקציה | להפעיל את התצוגה המקדימה. צ'אטים נעולים לא נתמכים |
| ענית ידנית, והטיוטה עברה ל**פג תוקף** | "נראה שענית ידנית — הטיוטה בוטלה" | תקין |
| הודעות ב-WhatsApp השני (Dual Messenger), ב-WhatsApp Business או ב-Secure Folder לא מקבלות טיוטה | האפליקציה מטפלת רק ב-`com.whatsapp` ורק בפרופיל המשתמש שלה. התראות מפרופיל אחר נדחות, כדי שתשובה לעולם לא תישלח מהמספר השני | מכוון. לא נבדק על מכשיר (R12) |

**העקיפה האופציונלית להסתרת תוכן רגיש** (החלטה מודעת שלך בלבד, לא נבדקה על המכשיר): הפקודה הבאה נותנת לאפליקציה לראות גם התראות "רגישות". **המחיר:** האפליקציה תראה גם קודי אימות (OTP) אמיתיים, של בנקים, של Google ושל WhatsApp עצמו. זו בדיוק ההגנה שהמערכת נותנת לך, ואם האפליקציה תיפרץ הקודים האלה יהיו חשופים. הסינון בשרת מסמן בקשות לקודים כ"רגישות", אבל זה לא מבטל את הסיכון. הרקע המלא נמצא ב-[ANDROID_FEASIBILITY.md](ANDROID_FEASIBILITY.md), ממצא F-2.

```bash
adb shell cmd appops set --user 0 ai.noa.personalbridge RECEIVE_SENSITIVE_NOTIFICATIONS allow
```

ביטול (חזרה לברירת המחדל):

```bash
adb shell cmd appops set --user 0 ai.noa.personalbridge RECEIVE_SENSITIVE_NOTIFICATIONS default
```

## 3. שגיאות שרת וחיבור

ההודעות מופיעות במסך **בית**, בכרטיס **תקלה אחרונה**, או במסך **חיבור לשרת**.

| הודעה / קוד | סיבה | מה עושים |
|---|---|---|
| **"השרת לא זמין"** (בכרטיס השרת: "מחובר, אבל השרת לא ענה בבדיקה האחרונה.") | (א) השרת לא רץ, או שהמחשב נכבה או נכנס למצב שינה. (ב) המנהרה נפלה, או שהכתובת שלה השתנתה (ב-Cloudflare Quick Tunnel זה קורה בכל הרצה). (ג) **השרת ענה 502, כלומר שגיאת מנוע**: חסר `BRIDGE_ANTHROPIC_API_KEY`, המפתח לא תקין, נגמר זמן ההמתנה (25 שניות), או ש-Anthropic לא זמין. האפליקציה מציגה גם שגיאות 5xx כ"השרת לא זמין" | בדיקה מהירה (למעלה). אם `/health` עובד, לבדוק בלוג של השרת שורה עם `"event": "engine_error"`. אם הכתובת של המנהרה השתנתה, לחבר מחדש עם קוד חדש |
| **401**: "החיבור לשרת בוטל — יש לחבר מחדש" | המכשיר בוטל (`revoke-device`, או **ניתוק מלא**), קובץ המסד נמחק, או ש**השרת הופעל מתיקייה אחרת** ולכן משתמש במסד אחר (`data\bridge.sqlite3` הוא נתיב יחסי) | להפעיל את השרת מתוך `bridge-service`, או להגדיר `BRIDGE_DB_PATH` מלא. אחר כך `create-pairing-code`, ובאפליקציה **חיבור לשרת** |
| **409**: "שגיאת סנכרון זמן מול השרת — בדוק שהשעון בטלפון מדויק" | השעון בטלפון או במחשב רחוק ביותר מ-5 דקות מהשעה האמיתית. נדיר: בקשה שנשלחה פעמיים | בטלפון: Settings ‏› General management ‏› Date and time ‏› Automatic date and time. ב-Windows: Settings ‏› Time & language ‏› Date & time ‏› Set time automatically ‏› Sync now |
| **429**: "יותר מדי בקשות, נסה שוב בעוד דקה" | יותר מ-30 טיוטות בדקה או 300 ביום למכשיר. בצימוד: יותר מ-10 ניסיונות בשעה. דרך מנהרה כל הבקשות נראות מאותה כתובת, ולכן המגבלה משותפת | לחכות. המונים נשמרים בזיכרון בלבד, ולכן הפעלה מחדש של השרת מאפסת אותם |
| **503**: "השרת כבוי כרגע" | `BRIDGE_ENABLED` לא `true` **בחלון שבו השרת רץ**, או שקיים הקובץ ש-`BRIDGE_KILL_SWITCH_FILE` מצביע עליו | `/health` יראה `"enabled":false`. להגדיר `$env:BRIDGE_ENABLED = "true"` ולהפעיל מחדש, או למחוק את קובץ ה-Kill Switch (אין צורך בהפעלה מחדש) |
| "קוד החיבור לא תקין או שפג תוקפו" (400) | הקוד שגוי, עברו יותר מ-10 דקות, הקוד כבר שומש, או שהוא נוצר במסד אחר (תיקייה אחרת) | ליצור קוד חדש **מאותה תיקייה** שבה השרת רץ |
| "קוד החיבור צריך להכיל 8 תווים (אותיות לועזיות וספרות)" | הקוד לא הועתק נכון | בקוד אין `0`, `O`, `1` או `I` |
| "הכתובת צריכה להתחיל ב-https:// ולכלול שם שרת." / "כתובת השרת חייבת להתחיל ב־https://" | הוזנה כתובת `http://` או IP מקומי | חייבים מנהרת HTTPS ([INSTALLATION_HE.md](INSTALLATION_HE.md), סעיף 3.4) |
| "כתובת השרת שגויה — בדוק את הכתובת" (404/405) | הכתובת לא מצביעה על שרת הגשר, או שיש בה נתיב מיותר | להזין רק את כתובת הבסיס של המנהרה, בלי `/health` ובלי `/v1` |
| החיבור נכשל ב-HTTPS, אבל `curl` מהמחשב עובד | תעודה בחתימה עצמית, או CA שהותקן ידנית. האפליקציה סומכת רק על תעודות של רשויות מוכרות | להשתמש ב-Tailscale או ב-Cloudflare, שמספקים תעודה מוכרת |
| בהפעלת השרת: `address already in use` (ב-Windows: `WinError 10048`) | הפורט 8787 תפוס, למשל כי השרת כבר רץ בחלון אחר | לסגור את השרת השני, או להגדיר `$env:BRIDGE_PORT = "8788"` ולעדכן את המנהרה |
| "התקבלה תשובה לא תקינה מהשרת" | משהו בדרך (המנהרה או proxy) החזיר דף שאינו JSON | לבדוק את `/health` דרך הכתובת החיצונית |

| **השליחה נכשלה**: "WhatsApp ביטלה את פעולת התשובה — לא נשלח" | WhatsApp ביטל את כפתור התשובה של ההתראה | לענות ידנית |
| **לא ידוע אם נשלח** | שגיאה באמצע ההעברה | **לא לשלוח שוב בעיוור.** לפתוח את השיחה ב-WhatsApp ולבדוק. רק אם ההודעה לא שם, לכתוב אותה ידנית |
| **הועבר ל-WhatsApp — אין אישור מסירה**, אבל ההודעה לא הגיעה | אין אישור מסירה. WhatsApp קיבל את הטקסט, אבל ייתכן שלא שלח אותו (למשל בלי אינטרנט) | לבדוק בשיחה. לא לנסות שוב מהאפליקציה (זה גם חסום) |
| "המכשיר נעול. אפשר לשלוח רק כשהמכשיר פתוח." / "יש לבטל את נעילת הטלפון לפני שליחה" | הטלפון נעול | לפתוח את הנעילה ולאשר שוב |
| "האישור כבר לא תקף — יש לאשר מחדש" | עברו יותר מ-2 דקות מהאישור, או שהגיעה הודעה חדשה או עריכה | לאשר מחדש |
| "לא ניתן לאשר את הטיוטה כרגע. …" | הגיעה הודעה חדשה, הטיוטה פגה, או שהופעלה עצירת חירום | לחכות לטיוטה המעודכנת |
| "השליחה הניסיונית כבויה בהגדרות" | השליחה כבויה. גם עצירת חירום מכבה אותה | **הגדרות** ‏› **פרטיות** ‏› **שליחה ניסיונית**, או להשתמש ב-**אשר והעתק** |
| "כבר בוצע ניסיון שליחה לטיוטה הזו. …" | הגנה מפני שליחה כפולה | מכוון |

## 7. לוגים לדיבוג (בלי תוכן)

### באפליקציה
כל הלוגים של האפליקציה עוברים דרך `SafeLog`, עם התג **`NoaBridge`**. הם מכילים רק שם אירוע, ולפעמים מספר (קוד HTTP, ספירה) או שם של סוג חריגה. אין בהם טקסט הודעות, שמות, מספרי טלפון, כתובות או טוקנים.

```bash
adb logcat -s NoaBridge
```

דוגמאות לאירועים: `LISTENER_CONNECTED`, `LISTENER_DISCONNECTED`, `LISTENER_REBIND_REQUESTED`, `NOTIFICATION_MAPPED`, `API_HTTP_ERROR code=401`, `API_IO_ERROR type=...`, `SEND_ATTEMPTED`, `SEND_NO_ACTION`, `SEND_REFUSED_LOCKED`, `SEND_REFUSED_DISABLED`, `DRAFT_NOTIFICATION_SKIPPED_NO_PERMISSION`.

> להריץ **רק** עם הסינון `-s NoaBridge`. בלוג המלא של המערכת (`adb logcat` בלי סינון) אפליקציות אחרות עלולות לכתוב תוכן. גם הפקודה `adb shell dumpsys notification --noredact` מציגה תוכן התראות מלא, ולכן לא לשתף את הפלט שלה.

### בשרת
שורת JSON אחת לכל בקשה, עם `method`, `path`, `status`, `latency_ms`, תחילית של מזהה המכשיר ו-`request_id`. בלי תוכן הודעות, שמות או טיוטות. שורות שכדאי לחפש:
- `"event": "engine_error"`: המנוע נכשל, והאפליקציה הציגה "השרת לא זמין".
- `"msg": "NOA persona fetch failed: ..."`: הפרסונה של נועה לא נטענה, והטיוטה נוצרה בלי פרסונה.
- `"msg": "NOA persona not configured or invalid; drafting without persona"`: חסר אחד מהמשתנים `BRIDGE_NOA_ENGINE_URL`, `BRIDGE_NOA_ENGINE_API_KEY` או `BRIDGE_NOA_AGENT_ID`, או שהערך שלו לא תקין.

לפירוט נוסף אפשר להפעיל `$env:BRIDGE_LOG_LEVEL = "DEBUG"`. לוג הגישה של uvicorn (`BRIDGE_ACCESS_LOG`) כבוי כברירת מחדל, ובכל מקרה הוא כולל רק נתיב וסטטוס.
