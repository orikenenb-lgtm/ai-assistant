# NOA Personal Bridge: Independent Code Review (Agent 33)

Scope: `noa-personal-bridge/android/core`, `android/app` (platform, ui, BridgeApplication, MainActivity,
AppController, manifest), `bridge-service/bridge_service`, `API_CONTRACT.md`.
Method: read-only review. Findings marked CONFIRMED were checked against the code, and where noted
reproduced with throwaway JVM tests kept outside the repo
(`/tmp/claude-0/-home-user-ai-assistant/f010ffe6-2a24-5262-b041-5bf173e21a8a/scratchpad/review/android/core/src/test/kotlin/ai/noa/bridge/core/ReviewReproTest.kt`,
4/4 tests show the described behaviour). Existing suites at review time: Python 348 passed;
`:core:test :app:testDebugUnitTest` green.

## Summary

No Critical finding. I found no path that sends without an approval issued by `approve()`, sends
twice for one approval, sends to a different conversation key than the approved one, or logs or
persists message content. The single-use guard, `sendMutex`, the consume-before-send order, the
handle `take()`, and the state machine hold up under the races I traced (debouncer fire vs. a new
message, an engine result after cancel, concurrent `sendApproved`, a send after `clearAll`).

The two High findings are both in the approval dialog's UI glue (`DraftDetailScreen.onConfirm`):
1. A stale dialog can approve old text over a newer conversation state.
2. Edits that end in whitespace can never be approved.

The Medium findings are about context and identity: what the drafter sees, and which notification a
conversation key or reply handle stands for.

## Checked and found sound (no finding)
- Explicit approval: `approve()` is reachable only from the dialog's confirm (`DraftDetailScreen`). The core requires AWAITING_APPROVAL, an exact text match, and not paused or stopped. `sendApproved` validates the token (identity, revision, conversation, SHA-256 and equality of the text, TTL, APPROVED state) under the lock and consumes it before the send.
- No double send: `sendMutex`, token consumption, and the `ReplyActionRegistry.take()` single-use handle. A SENDING draft is excluded from `activeDraftLocked`, so new messages open a new draft. SendTracker deduplicates per draft id.
- Debouncer and coordinator races: a superseded timer never fires (identity check). A late fire after a new message processes the merged draft once; the second fire is ignored because the state is no longer DEBOUNCING. Stale engine results are dropped by the revision and state check.
- Logging and persistence: Android `SafeLog` takes only enum codes and class names. Server logging uses an allow-list formatter and a redaction filter. No content goes to SQLite. Backup and D2D are excluded. `FLAG_SECURE` is set. The draft notification has a name-free public version and no actions.
- API contract: field names, limits (the client counts UTF-16 units, which is stricter than Python's code points), UUID v4 `request_id` echo, headers, and status mapping all match `API_CONTRACT.md` v1.1.
